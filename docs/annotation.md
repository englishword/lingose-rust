# P3.1 基础纯文本标注

`annotate_ips(text)` 和 `annotate_ips_with_skip_top(text, 0)` 已接入正式离线词库。
本阶段实现分词、直接采用的 IPS、字符簇对齐、大小写和未知词中括号。
`the` 上下文、缺源后的缩写/复合/词形推导属于 P3.2；正频率阈值属于 P3.3，尚未完成。
本阶段不是完整 Python 文本算法或 P4 全量/性能验收。

## 扫描与资源

- 先检查负阈值，再检查 NUL；空文本和首尾空白合法。
- 扫描集合为固定 Python 3.12.4 / Unicode 15.0 的 `isalnum()` 加全部 `M*` 类别。
  词内 `-'’` 只在已有词段且后继标量为 Python `isalpha()` 时连接。
- 仅整个词段匹配 `[A-Za-z]+(?:[-'’][A-Za-z]+)*` 才转换。
  数字、非英语字母、Mn/Mc/Me 或变体选择符会使相连的整个词段原样保留。
  Rust 内部使用 UTF-8 字节区间，区间始终落在标量边界。
- 没有完整英语词段时，对任意非负阈值直接返回输入，不调用资源加载器。
  有英语词段且阈值为零时只加载主词库；损坏/不兼容错误原样传播并按加载器规则缓存。
- 有英语词段且阈值大于零时，在访问资源之前返回
  `NotImplemented { operation: "annotate_ips_with_skip_top" }`。
  P3.3 将接入上限 5062 和完整屏蔽规则，当前没有忽略筛选请求的成功路径。
- 原样复制所有词段间隙，保留 CR/LF、制表符、标点和非英语文本。
  本函数处理纯文本，不解析 HTML；标签中的英语也会作为纯文本处理。

## 直接匹配与转换

按精确原词、弯撇号换直撇号、原词小写、小写直撇号四种拼写依次查询，去除重复。
首个存在词条立即停止，即使其状态是允许缺源回退或明确阻断。
标注输入域仅含 ASCII 字母及三个分隔符，因此 ASCII 小写与 Python 的小写等价；
不调用简单查询的 `lower_variant`。`APPLE` 可以标注，简单查询仍遵守其原有回退限制。

从 `AnnotationState::Available` 读取单个有效采用 IPS，按 `M*` 分组为完整字符簇。
每个输入标量须与一个字符簇对齐，基础字母须相同。分隔符输出输入原样，
英语字母依输入逐字大小写转换，支持全部 52 个双线体形式及精确的 `w̄ ↔ W̅` 特例。
未知词、不可用/阻断词条、长度或基础字母不匹配均输出 `[原词]`。
`Fallback` 与 `Absent` 保留不同内部状态，后续阶段可以在原有顺序中加入推导；本阶段均输出中括号。

NFD 只用于**判断能否对齐**，输出始终对原始字符簇作完整大小写转换，不输出规范化字符串。
允许的 NFD 附加标记为 U+0300、0302、0303、0304、0305、0307、030A、0323。
生成表固定 243 个可用 NFD 基础标量、9 个可用附加标量（包含分解成 U+0300 的 U+0340），
以及 54 个精确特殊字符簇。附加标量的大小写均为恒等；规范化重排不影响集合判断，
因此初始标量及各后续标量的受限 NFD 谓词等价于 Python 的整个字符簇判断。
双线体加附加标记不属于精确特例，会被拒绝。无需实现或依赖通用 NFD 运行库。

## 可重复性与验证

[Unicode 身份](annotation-unicode.json)记录 Python/源代码/许可/生成器身份及表摘要。
`tools/generate_annotation_unicode.py --check` 拒绝基线、解释器、参考许可或现有输出漂移。
Unicode 表约 40 KB，沿用 [Unicode License V3](../third_party/unicode/LICENSE.txt)，无新增 Cargo 依赖或 MSRV 要求。
Rust 不调用编译器的 Unicode 分类、大小写或规范化实现。

`tools/generate_annotation_vectors.py --check` 直接从固定 Python 捕获预期，核对完整输入身份；
现有 P0 文件不变。向量包含 83 个扫描输入、497 个基础判定、1,024 个字符簇转换，
其中覆盖全部 298 个单标量可接受基础和全部双线体形式。
公共测试包含 5 条固定 P0 及 10 条直接标注/无词段文本，默认和显式零阈值共 30 次完整输出核对。
生成器按 Python 保存状态检查文本无需成功的 P3.2 推导，不通过比较 Rust 输出来选择样本。

Rust 还逐一核对全部 1,112,064 个 Unicode 标量的扫描/NFD 域/有效大小写摘要；
独立 wire 夹具覆盖首个存在词条阻断、精确大小写/撇号优先、错误与无法对齐路径。
公共测试覆盖所有权及 16 线程并发，损坏资源测试覆盖真正的分词无资源路径和零阈值无频率路径。
独立只读复核另外对全部标量及 200,000 组确定性组合字符簇核对 Python，未发现算法差异。

[离线 release 证据](annotation-verification.json)由
`tools/check_queries.py --annotation` 生成：复制最小构建输入，以 locked/offline/release 构建，
把 5 个测试二进制移到仅含二进制的目录执行；核对源资源与构建输入前后摘要。
旧 P2.3/P2.4 报告保留。当前 58 项 Rust 测试和 5 项文档测试通过（另有 1 项旧手动探针忽略），
56 项 Python 回归、311 条 Python 固定向量、五个生成器检查、fmt、Clippy、文档构建及标注示例通过。
实际验证仅 Windows MSVC / Rust 1.93.1；没有执行最低版本、正式归档、发布或性能验收。

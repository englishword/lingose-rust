# 公共 API release 性能验收（P4.2）

在 P1.2 规定的完整预热、未清理 OS 缓存条件下，全部运行时间、原始资源和内存预算通过。
数值预算 [performance-budget.json](performance-budget.json) 未修改。原始样本、工具/输入/
可执行文件身份及自动判定见 [performance-verification.json](performance-verification.json)。
本轮未发现需要修改库实现的超限项；生产代码、数据、依赖和 P4.1 历史证据保持原样。
真实 `.crate` 归档体积及独立打包消费仍由 P5.3 验收。

**新文件路径的首次执行仍超过 300 ms**，主要额外时间位于父进程等待 `Popen` 返回的创建阶段，
不调用 Lingose 的同一二进制也会出现。该结果完整保留并单列，不计入固定预热条件下的
7 个新消费进程统计；不能据正式统计声称新文件第一次启动也达标。具体 OS 组件未确定。

## 条件和覆盖

- Windows 11 build 26200 / AMD64，Intel i7-1360P，16 逻辑处理器，物理内存
  34,067,963,904 字节；Rust/Cargo 1.93.1、MSVC、LLVM 21.1.8，Python 3.12.4。
- 独立消费工程 [performance-probe](../tools/performance-probe/Cargo.toml) 使用 release、
  thin LTO、codegen-units=1、strip=true。主 crate 的 profile 和生产依赖不变。
  在 `.local` 最小源码副本中 `--offline --locked` 构建；运行目录只有可执行程序和
  明确列出的查询/语料/期望文件，无 Python、源码或外置词库参与 Rust 运行。
- P4.1 全部输入身份先核对，再核对复制的输入与输出。正式性能输入为固定完整
  10,000 / 100,000 词语料（92,862 / 930,474 UTF-8 字节），没有截断。
  每次固定长语料标注输出均在计时后与 P4.1 本轮捕获的完整 Python 字符串逐字比较。
- 每个正式时间场景 7 个独立进程样本；Rust `Instant` 测内部调用，Python
  `perf_counter` 测启动至退出。保留原顺序、min/median/max、nearest-rank p95，
  7 样本的 p95 为最大值；无异常值剔除。未固定 affinity、清理 OS 缓存或控制桌面负载。
- 先单独保留新复制二进制的首次执行及启动诊断，再执行一次不计入统计的完整预热，
  然后采集 7 次正式冷调用、首次频率调用及热场景；与 P1.2 的预热条件一致。
  每次冷调用仍是新进程、尚未初始化库，只调用一次公共 `ips("apple")`。
- 主库初始化使用首次 `ips("apple")`，频率初始化使用主库已加载后的首次正阈值
  标注 `annotate_ips_with_skip_top("the", 1)`。两者含少量公共调用开销，
  因而是加载/验证/建索引时间的保守上界，没有用私有接口绕过实际检查。
- 热查询包含参数检查、精确/条件小写规则与完整 owned 结果的分配和释放。
  全部 50,335 精确词键各两遍；另有 32 个大小写、Unicode、未知词混合词各 2,000 遍。
  覆盖 ipa、ips、ism、ipsm、root_lemma、默认/en/zh meaning、默认及全部 24 类 kind。
  四组大小写别名共用实现，其等价性沿用 P4.1 全量结果。
- labels 完整复制 10,000 次；kind_list 全部 24 类、209,759 个完整成员复制 10 轮，
  时间除以轮数 10；默认 CET4 列表额外复制 100 次，作为补充指标。
  热查询 p95 是批次平均每操作耗时的分位数，不是单次调用的尾延迟。

每个内存场景用 3 个独立新进程、管道暂停协议与 Windows
`GetProcessMemoryInfo(PROCESS_MEMORY_COUNTERS_EX)`，分别记录加载前/后绝对值与 delta。
下表取该场景所有样本最大值，不取平均数。计数包含进程运行时，不能解释为净堆占用。

| 场景最大值 | 实测字节 | 固定上限字节 |
| --- | ---: | ---: |
| 两资源加载后工作集 | 16,433,152 | 33,554,432 |
| 两资源加载后私有提交 | 2,547,712 | 8,388,608 |
| 两资源加载后峰值私有提交 | 2,576,384 | 12,582,912 |
| 100,000 词标注峰值工作集，三个阈值各自检查 | 21,110,784 | 100,663,296 |
| 100,000 词标注峰值私有提交，三个阈值各自检查 | 9,302,016 | 67,108,864 |

标注内存进程从未加载状态开始，包含完整输入、完整输出、资源加载及算法临时分配。
结果存活时读取累计峰值，之后才载入 Python 期望全文进行比较，避免期望缓冲区污染测量。
峰值包含已释放的暂存；没有从峰值减去输入、输出或进程基线。

7 个新进程各用屏障同时释放 8 个首访线程；每线程对完整 100,000 词文本执行阈值
0/1000/5062 之一并全文核对，再执行公共查询。共 56 次结果一致，首访及共享资源复用通过。
8 线程整批墙钟为 220.22–279.02 ms（包括比较、线程创建等），只作补充观察；
未给并发吞吐设置新预算，也未把它替代单次标注时间或单进程内存验收。

## 首次文件执行诊断及剩余边界

正式探针在新路径第一次执行为 **534.24 ms**，其中父进程 `Popen` 返回前的创建阶段
为 **495.69 ms**，库内首次公共调用为 **26.78 ms**。这次仍超过 300 ms，原始样本未删除。
另外复制四个相同摘要的二进制到新路径，交替先执行无查询 control 或公共 cold 模式：

- 两个无查询 control 的首次墙钟为 558.97 / 545.10 ms，创建阶段为 547.25 / 537.58 ms。
- 两个首次查询进程墙钟为 625.12 / 583.86 ms，创建阶段为 586.13 / 545.92 ms。
- 随后同文件 control 墙钟为 7.90–26.94 ms，cold 为 42.68–45.32 ms。

该对照把 P2.2 所见大部分额外耗时定位到库调用之外、与新文件路径首次执行有关的
父进程创建等待；没有 OS 追踪，不能确定是哪个 Windows 组件或直接归因某个扫描器。
也未精确追踪单个 `CreateProcess` 系统调用。固定预热条件下的运行预算达标，
**不构成新文件首次执行、其他机器、MSRV 或其他平台的延迟保证**。

重复 `n't` 超长词的补充诊断（无固定预算）在 256 / 1,024 / 4,096 次尾缀下为
0.323 / 2.060 / 29.721 ms。原生栈风险已由 P3.2 消除，渐近二次成本仍存在；
本次完整真实语料明显在预算内，保留现实现，不增加未经需求支持的缓存或特殊快路径。

## 验证与重现

新增 9 项 Python 工具测试覆盖单位/操作数转换、完整场景与精确输出标记、样本数量、
p95 极值、逐个绝对内存峰值，以及失败子进程的输出/错误/已有内存记录保留。
子进程失败或超时也会留下日志与失败状态；内存握手有整体 180 秒 watchdog。

本轮 70 项 Python 测试、102 项 Rust 测试及 5 项文档测试通过，根工程与开发探针
fmt/Clippy（`-D warnings`）通过。库实现及 P4.1 所有固定输入身份逐项保持一致，
因此沿用 P4.1 的 1,862,690 项全量差分结论，未重新捕获或改写历史证据。
未进入 P5 的最低版本、文档整备、打包和 dry-run，也未发布。

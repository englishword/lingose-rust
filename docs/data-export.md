# 正式数据导出与校验（P2.1）

正式产物由 `tools/export_data.py` 从 P0 固定的**已安装 Python Lingose 0.2.0**
实际查询数据库生成。它不读取 `.local/layout` 原型或相邻源码仓库中的数据库。
格式、静态镜像与共享索引选型及预算继续遵循 [data-layout.md](data-layout.md)。
P2.1 仅完成资源与开发期验证，Rust 加载器和公共查询尚未实现。

## 产物

| 文件 | 内容 |
| --- | --- |
| `data/lexicon.bin` | 50,335 精确词键、七个独立可空字段、标注三态、24 分类及 209,759 个有序成员 |
| `data/frequency.bin` | 10,620 精确小写频率词键及最小原始 NUMBER，保留短语、标点和序号缺口 |
| `data/manifest.json` | 版本、计数、完整资源 SHA-256、P0 输入身份、生成文件摘要及状态统计 |
| `src/data_meta.rs` | P2.2 加载器将使用的预期格式/数据版本、完整摘要和资源计数；当前未接入主 crate |
| `data/SOURCES.json` | 每个资源的来源、快照身份、改编说明、作者及许可证引用 |
| `data/UPSTREAM-SOURCES.md` | P0 固定的 Python 上游来源声明，逐字节保留 |

主词库为 **10,259,743 字节**，SHA-256
`0f00506a54d8360c3346df6347790811dfd145b98814aa1c12b98c69c0542bd6`；
频率资源为 **200,272 字节**，SHA-256
`af2813952a826e082a7c683472d067d071a855c0aba47c28e90c1f4829384264`。
这些是原始资源体积，最终 `.crate` 在 P5.3 验收。

正式资源与 P1.2 固定镜像的字节身份相同，源于相同的 v1 业务投影；
本轮通过正式流程重新生成并独立逐记录核对，未复制原型作为生产产物。
manifest 不含时间戳或本机绝对路径；构建和运行不需要 Python、SQLite、相邻仓库或联网。
`.gitattributes` 固定生成产物及摘要保护文件的字节，避免 Git 换行转换破坏身份。
`Cargo.toml` 的发布保护与待 P5.3 调整的 include 清单仍保留。

## 保护和投影规则

1. 入口固定 P0 基线文件的 SHA-256
   `9891742574b4c3c5ef5e420cb17d380094601803cddfc73e55062b7fccd54f01`，
   再调用 `require_baseline()`，核对安装包版本、实际路径及代码/数据库指纹。
2. SQLite 必须已经存在，以 `mode=ro`、`query_only` 打开；拒绝 journal/WAL/SHM，
   并使用 `no_restore()` 禁止恢复。导出后再次核对完整输入指纹，成功后才允许写产物。
3. 一次受保护投影保留每个精确词键，包括无法标注的记录。文本字段仅取 available
   值；IPA、IPS、IPSM 独立选择，未选候选不导出。空字符串、换行与原始组合符不改写。
   可用值必须符合声明类型，不能用真值转换把 `false`、`0` 或非法类型吞为空值。
4. IPSM 跟随实际存储的依赖 ID、所属词条、字段、状态、算法版本及 UTF-8 文本摘要。
   依赖可以指向同词条的另一发音；不重新推导。失效结果为空，且计数明确记录。
5. 标注三态为 0=阻断、1=纯缺源可规则回退、2=已有非空 IPS。合法未知词由词键不存在
   表达。本快照为 246 条状态 1、50,089 条状态 2；状态 0 由隔离夹具覆盖。
6. 分类布尔值按精确 JSON 类型处理；位图与完整成员集合必须一致。词表沿用已固定的
   Python root/rank/word SQL 顺序，rank 不成为公共字段。频率保留原始 1..5062 阈值。
7. 所有字符串按原始 UTF-8 字节去重排序，null ID 为 `0xffffffff`。两个资源各有自己的
   字符串池；结构由独立解码器完整验证后才写入。来源清单和 Rust 常量取自同一投影结果。
8. 写入前预检全部目标；已有文件必须逐字节一致，缺失文件仅 `--write` 可创建。
   发现差异时保留原文件。工具不提供静默覆盖基线或生成产物的选项。

## 重现

以下命令只供开发使用，要求 P0 固定的已安装包和数据库仍可只读访问：

```powershell
python tools/export_data.py --check
python tools/verify_data.py
python -m unittest discover -s tests -p 'test_*.py'
```

首次建立缺失产物可用 `--write`，它同样拒绝覆盖不同的已有内容。
在独立目录重建（输出保持 `data/` 和 `src/` 的相同相对结构）：

```powershell
$env:PYTHONHASHSEED='20261016'
python tools/export_data.py --write --output .local/export-replay
python tools/verify_data.py --output .local/export-replay
```

源身份发生变化应先完成新的明确审计；不能改写 P0 指纹来让检查通过。
需要调整导出器或格式时，先在新的隔离目录生成并审查差异，再明确更新版本及正式产物。
单元测试只在一次性夹具中模拟输入改变、类型错误、依赖失效和输出篡改。

## 验证范围

`tools/verify_data.py` 不导入正式编码器或探针解码器。它独立校验头、固定版本、
计数、所有节边界、UTF-8、严格排序、全部引用、分类范围/位图/成员等价、
标注三态和频率范围，并检查 manifest、预期 Rust 常量、来源身份和原始上游声明。

全部 50,335 条记录通过一个只读连接调用已安装包的 `query._lookup`，独立对照
七个字段及全部分类布尔值；使用 `annotation._Annotator.exact` 对照每词的标注状态。
全部 24 类的完整顺序通过实际 `query.kind_list` 对照；全部频率行逐项比较。
154 条适用的 P0 查询/标签/完整词表向量再次核对。
具体机器、计数、摘要和结果见 [data-verification.json](data-verification.json)。

隔离夹具覆盖：真实库没有的阻断状态、冲突/待审/无效候选、独立发音列表、
缺失/失效/跨发音有效的 IPSM 依赖、空字符串/null、换行、组合符与非 BMP 字符、
合法 false/0 及非法类型、源文件在投影后发生改变、拒绝覆盖、输出摘要篡改、
错误版本/计数/偏移/UTF-8/引用/排序/分类/频率以及元数据漂移。

本轮不验收生产 Rust API、并发加载、完整文本标注、MSRV、跨平台或性能预算。
生产数据加载从 P2.2 继续，完整公共 API 差分及性能验收仍在 P4。
项目许可证及上游作者署名保持不变，第三方材料保留自身许可证；
来源清单如实记录固定参考未附独立 Frequency List 许可文本，最终分发声明核对留在 P5.1。

## 测量条件与解释

库探针使用既定 release profile（thin LTO、codegen-units=1、strip=true），
不改正式 workspace 的默认 release profile。使用同一机器和完整语料：
10,000 / 100,000 英语词，各 92,862 / 930,474 UTF-8 字节，摘要逐项核对原预算。
每个时间场景完整预热一次，再采七个独立新进程；保留全部样本，中位数和
nearest-rank p95 分别比较原上限，七样本 p95 等于最大值。

新路径二进制的首次执行另存；正式七样本是固定预热条件下的新消费进程。
既有新路径首启超过 300 ms 的历史事实保留，新版首启另报，不能将预热后的通过
写成未经预热的启动保证。未清理 OS 缓存、固定 CPU affinity 或控制全部桌面负载。
热查询分位数是批次平均单次耗时，不是单次调用尾延迟。

内存沿用 Windows GetProcessMemoryInfo 的工作集、私有提交及峰值计数，加载场景和
三个阈值的完整 100,000 词标注各采三个独立进程，逐个检查绝对上限。
并发探针验证八个同步首次调用者的查询及完整标注，不据此声明吞吐预算。

CLI 独立测量 26 个场景：普通/JSON 单词查询，以及两种文本规模 × 三个阈值 ×
普通/JSON × stdin→stdout / 文件→文件。每场景一次完整预热、七次正式新进程，
共 182 次正式进程；首启另存。每个完整输出在计时后对照本轮 Python 期望，
JSON 核对精确键、类型和完整字符串；文件输出同时要求 stdout 为空。
CLI 的 perf_counter 覆盖进程创建到退出，包括解析、库调用、管道或文件 I/O；
不含父进程验值。文件场景的预热创建目标，正式样本覆盖已有目标，没有 fsync。
CLI 使用 workspace 默认 release profile；没有新增数值预算，也不套用库预算。

构建超时留证另用明确的合成 TimeoutExpired 夹具检查：保留部分 stdout/stderr
原始字节、超时/失败状态，不生成成功收据。正式测量仍使用真实 Cargo/CLI。

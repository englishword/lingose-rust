# 离线资源加载与索引（P2.2）

`src/data/` 已实现正式 v1 解析、共享只读索引、独立延迟初始化及错误缓存。
它直接内嵌 P2.1 的两份资源，使用 `src/data_meta.rs` 固定的版本/计数/摘要，
不解析运行时 JSON manifest、不下载、不恢复缓存、不打开文件或数据库。
公共查询仍返回 `NotImplemented`，P2.3/P2.4/P3 将依次接入内部入口。

## 解析和借用

- 首先检查头/magic，再精确检查格式、两种 schema、IPSM 算法及两个源数据版本。
  不兼容返回 `Error::IncompatibleDataVersion`，其优先级高于该头改变导致的摘要不符。
  其余损坏返回 `Error::Data`，resource 为逻辑名称 `lexicon` 或 `frequency`。
- 校验完整字节数、SHA-256 和六项固定计数；节长度计算使用 checked arithmetic，
  在切片、解码和分配前验证总边界及主词库/频率的节分离。
- 验证整个池及每个字符串边界的 UTF-8、原始字节严格排序、所有字符串引用、词键合法性、
  三种标注状态、最多 32 位分类、完整分类范围/成员唯一性/位图等价、频率序号及精确键顺序。
  不对字符串做 Unicode 规范化；空字符串与 null 分开。
- 冻结的 10,620 个频率键全部为 ASCII，测试逐条证明这一快照属性。解析器检查 ASCII
  大写、空/NUL 及字节顺序，其他 UTF-8 原样保留，不借用编译器 Unicode 表来替代
  Python 3.12/Unicode 15.0 小写规则。正式资源的精确拼写由固定摘要保证。
- 解析后保留字节切片和 UTF-8 字符串池的借用视图。HashMap 的键为资源内的
  `&'static str`，值为词条位置；不复制整库字符串。分类业务顺序直接读取成员表。
  HashMap 随机种子不参与业务排序。频率在自身的有序键表中二分查找，不建立阈值集合。

## 复用和访问顺序

两个资源各有独立 `OnceLock<Result<_, Error>>`。首次成功后只读复用；首次失败缓存
原错误，后续返回其克隆。词不存在由加载成功后的 `Option` 表达，加载失败不会变成未知词。
热路径没有全局查询互斥锁，也不会重新解析、分配全库字符串或重建词键索引。

内部 `for_annotation(has_tokens, skip_top)` 集中管理访问顺序：无可转换 token 时返回
无需资源；阈值为零只加载主词库；非零先频率再主词库。`has_tokens` 留给 P3 的正式
分词器提供，P2.2 的策略测试不构成空文本、非英语文本或完整标注的公共 API 验收。
频率成员检查使用原始 NUMBER 的包含阈值，并把非零超上限值限制为 5062。

本阶段尚未被公共入口调用的 data 模块有局部 `allow(dead_code)`，避免通过提前接入
未完成业务逻辑消除警告。随着 P2.3/P2.4/P3 接入，逐步移除此过渡豁免；不改变公共 API。

## 验证与重现

```powershell
$env:CARGO_HOME=Join-Path (Get-Location) '.local/cargo-home'
cargo test --offline --locked --lib data::
cargo clippy --offline --locked --all-targets --all-features -- -D warnings
python tools/check_loader.py --write
```

- 独立 wire 夹具不复用正式编码器或探针实现，覆盖空/null/组合符/非 BMP、32 位分类、
  标注三态、完整顺序、频率缺口、每种版本/计数/摘要/结构错误、全部截断及逐字节变异无 panic。
- 全部正式词键索引/字段视图均检查落在原始嵌入资源中。完整字段、状态、有序分类及频率
  的 Rust 逻辑流 SHA-256 等于 P2.1 独立 Python 固定值
  `30c5cd54d9fcf6cc7bdf0d8d99dd7d87f9763e3f65189596aae3c972702d2bd3`。
- 16 个线程同时首访验证各资源只初始化一次、所有线程得到相同对象/借用输出；
  并发失败同样只初始化一次。另测独立加载、成功/失败热复用、资源访问顺序及阈值包含性。
- `tools/check_loader.py` 将 Cargo/src/数据等必要文件逐字节复制到 `.local` 新隔离目录，
  使用准备好的本地依赖缓存进行 `--offline --locked --release` 构建。随后把测试二进制
  单独复制到不含源码/数据的目录，直接运行七个全新进程。临时目录保留供复核。
  每进程记录两资源首次加载、初始化次数、100,000 次缓存/精确键查找及进程墙钟时间。
  样本、统计、机器/工具链、数据/代码摘要及依赖信息在
  [loader-verification.json](loader-verification.json)。
  加载器不访问源文件/数据文件的判断来自源码复核及独立二进制运行条件，未做系统调用跟踪。

归档复核发现 const 资源引用让测试二进制各嵌入两份完整资源，已改为共享 static 引用。
最终测试二进制为 11,355,136 字节，各完整资源只出现一次（原为 21,814,784 字节）。
最终七次主资源初始化（含索引）中位数/最大值为 23.42/33.87 ms，频率为
0.599/0.616 ms。两轮首进程墙钟分别有 806.48/732.77 ms，启动开销原因尚未隔离；
旧 const 轮和最终 static 轮的全部原始样本及身份分别保留。P4.2 将用真实公共 API
重新检查冷进程预算，不据此放宽预算。上述测试二进制大小不是最终 .crate 大小。

这些计时是私有加载器/索引检查；不含公共参数/大小写规则、拥有所有权的输出、完整文本
标注或内存验收。冷进程不清理操作系统文件缓存。测试模式带初始化计数器。
不把这些结果写成 P4 性能预算已通过，也不是 P5.3 打包消费或 crates.io 验收。

新增运行依赖仅 `sha2` 0.10.9 系列；开发过程复用 `.local/cargo-home`，未修改全局 Cargo
配置。依赖声明的 MSRV/许可证在证据中如实记录，缺失声明保留 null；实际 Rust 1.85
及其他平台测试仍在 P5.2。本轮继续使用 Windows MSVC / Rust 1.93.1。

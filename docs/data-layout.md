# Rust 数据布局决策（P1.2）

选择**静态二进制镜像 + 启动时建立共享只读 HashMap 词键索引**，不对运行时镜像预压缩。
主词库与频率表使用两个独立内嵌资源、分别延迟初始化。选择基于完整投影的四方案
release 实测，原始结果见 [layout-probe-results.json](layout-probe-results.json)，
测量方法与后续验收预算见 [performance-budget.md](performance-budget.md)。
此处固定方案；P2.1 的[正式导出与独立验证](data-export.md)已完成。
P2.2 的[生产加载器与索引](data-loader.md)已完成，公共查询仍属于后续 P2 任务，
探针保持开发期实验身份。

## 完整数据与候选

本轮按 [P0 基线](reference-baseline.md)保护读取已安装 Python 0.2.0 的实际数据库，
前后指纹一致。每个方案均包含相同的 50,335 个实际词键、全部必要有效公开字段、
标注回退资格、24 类共 209,759 个有序成员和 10,620 个频率词键。
数据未写回源库或相邻 checkout。

| 方案 | 两资源内嵌字节 | 主词库校验/加载中位数 | 建词键索引中位数 | 冷进程退出中位数 |
| --- | ---: | ---: | ---: | ---: |
| static：原始镜像 + 二分 | 10,460,015 | 28.00 ms | <0.001 ms | 71.81 ms |
| static-hash：原始镜像 + HashMap | 10,460,015 | 27.95 ms | 2.26 ms | 76.98 ms |
| gzip：解压镜像 + 二分 | 3,897,357 | 67.88 ms | <0.001 ms | 113.13 ms |
| hash：解压镜像 + HashMap | 3,897,357 | 64.70 ms | 2.04 ms | 112.08 ms |

主词库加载包含 SHA-256、UTF-8 及全结构校验。频率表另需约 0.75 ms（静态）或
1.46–1.51 ms（gzip）。JSON 的 load_ms 是两资源加载之和，**不包含 index_ms**；
比较完整初始化须另加索引时间。冷进程退出还包含运行时启动、完整逻辑校验、JSON
及退出；不是公共 API 首次调用的计时，也没有清理操作系统文件缓存。

static-hash 的热查询投影中位数约 0.05–0.38 微秒/次，包含真实 Vec/String/Option
结果分配及释放；这些是精确键投影，不含生产参数验证或大小写回退。
全部 24 类词表一轮完整复制约 18.21 ms。该方案在 100,000 词布局负载的阈值
0/1000/5062 下分别为 21.78/59.03/55.35 ms；这个 ASCII 负载会拆开撇号和连字符，
不重建标注文本，**不能当作 annotate_ips，也不能据此计算相对 Python 的产品加速比**。

static-hash 三次加载后进程工作集约 15.46–15.48 MiB、私有提交约 2.26–2.30 MiB；
gzip/hash 的峰值私有提交约 25.85–25.92 MiB。内存包含运行时；静态资源主要为
文件映射页，解压数据主要为私有内存，二者不能只比较一种内存指标。
选择 HashMap 约增加 1.6 MiB 私有内存，相对于静态二分减少了本轮词键查找成本。
额外约 2.3 ms 的索引建立开销符合本项目反复查询及长文本用途。

## 分发体积

- 主词库镜像：10,259,743 字节；频率镜像：200,272 字节。
- 两份 gzip 资源：3,821,171 + 76,186 = 3,897,357 字节。
- 使用当前源码、示例、许可证及完整原始资源构造的**真实 gzip 压缩 tar 估算**为
  3,923,273 字节；预压缩资源版本为 3,874,364 字节，仅相差 48,909 字节。
  因 `.crate` 本身会压缩，不能用原始镜像的 10.46 MB 推断最终归档超限。
- 上述仅为原型归档估算，不是 `cargo package` 生成的 `.crate`。最终 Unicode 等
  必要资源、分发清单和实际 `.crate` 在 P5.3 检查。本轮把总归档预算固定为
  5,000,000 字节；上游当前文档的默认上限为 10 MB，正式发布前再次复核。
  [Cargo 发布说明](https://doc.rust-lang.org/cargo/reference/publishing.html)

本方案不携带约 89 MB 的完整 Python 压缩库、审核表、来源逐行记录或维护工具。
静态与压缩探针的可执行文件分别约 10.70 MB 和 4.20 MB；这是本机探针二进制大小，
不等同于 `.crate`、任意消费程序或最终链接后的增量体积。

## v1 格式、排序和空值

P2.1 采用 [原型格式说明](../tools/layout-probe/FORMAT.md)固定的 v1 逻辑布局：
112 字节头、u32 小端整数字段、字符串偏移表、40 字节词条记录、标签表、
有序分类成员 entry 索引、频率记录和 UTF-8 字符串池。主词库的 frequency_count=0；
频率资源的 entry/label/member_count=0，各有自己的字符串池与完整 SHA-256。

- 头中保存 magic、格式版本、计数、源 schema 版本、IPSM 算法版本和两个源数据版本。
  P2.1 另生成包含计数、算法、源身份、资源 SHA-256 和许可的 manifest 及 Rust 常量。
  生产初始化核对预期版本、完整摘要及所有边界/索引不变量；不接受只写非零版本的任意数据。
- 字符串按原始 UTF-8 字节去重和排序，不执行 Unicode 规范化。合法 UTF-8 的字节
  字典序与本项目需要的 Unicode 标量/BINARY 次序一致；不使用 JavaScript UTF-16 顺序。
- u32 字符串 ID 的 0xffffffff 表示不可用值；空字符串使用真实 ID，不能与 null 混淆。
  数字、布尔或空值类型不符合字段契约时报告数据错误，不能靠真值判断吞掉 false 或 0。
- 全部实际 entry 均保留，按精确 word 的 UTF-8 字节排序。三个发音引用各自表示
  当前基线选中结果的零/一个值，允许列表长度不同，不按索引配对；将来若改变这一
  格式能力必须提升格式版本，不静默解释成新布局。
- IPSM 只保留仍有效的采用值，跟随实际派生记录的依赖 ID、状态、算法版本和
  UTF-8 SHA-256 校验，不重新计算或取其他候选。当前 invalid_selected_ipsm=0
  只统计本轮对源 available 值额外拒绝的数量，未计入源字段已标记 invalid 的记录。
- 标注状态 0=已存在但阻断，1=纯 missing/source_record_missing 可进行文本规则回退，
  2=已有非空 IPS。未知词由精确键不存在表达，不能省略状态 0/1 的 entry。
  本快照实际为状态 1 共 246、状态 2 共 50,089，没有状态 0；夹具仍须覆盖状态 0。
- 分类标签按配置顺序，最多 32 个，当前 24 个；位图 bit 位置对应标签数组位置。
  独立预存全部有序 entry 索引，保持 Python 已保存 root/rank/word 的排序。
  运行时无需携带 rank。当前数据已核对 kind 的 JSON 布尔语义与 kind_list 的
  原始 `value_json='true'` 成员集合完全一致，不把这个事实推广到任意损坏输入。
- 频率独立保留 10,620 个精确小写词键及最小原始 NUMBER，包括短语、带标点 token
  和序号缺口；按 UTF-8 字节排序二分查找，不重排为连续 rank。

生产资源均由 `include_bytes!` 随 crate 分发，没有 build.rs、词库下载或文件缓存恢复。
主查询先精确匹配，再按 P0 的有条件小写回退；文本使用其独立的匹配规则。
Rust 编译器自带的 Unicode 版本不自动成为 Python 3.12/Unicode 15.0 的行为基线，
P2/P3 仍需明确验证相关分类、大小写及规范分解约定。

## 复用、错误和并发

- 主词库使用 `OnceLock<Result<Lexicon, Error>>` 延迟初始化。镜像保留静态只读
  字节视图；词键 HashMap 使用借用的 `&'static str` 和 entry 索引，不克隆整库字符串。
  建立完成后不再写入，热查询只复制公开输出所需的值。
- 频率资源使用另一个 OnceLock，保留静态有序键及原始阈值，不按每个 skip_top
  重建全表。非英语/空文本无需资源，skip_top=0 不触发频率初始化。
  对含可转换文本的非零阈值，按 Python 先检查频率资源，再检查主词库。
- 初始化错误也缓存为 Err，随后返回该错误的克隆；不能转换为空列表或未知词。
  无文件下载、修复、回写和隐式恢复。数据版本不兼容与一般损坏错误继续分开。
- OnceLock 的同步初始化机制让多个线程共享同一份索引；不为每个词重载资源，
  不用全局查询互斥锁。并发首访、错误缓存和多线程读取一致性已在 P2.2 单独验证，
  见[加载器说明](data-loader.md)；P1.2 单进程布局测量本身不代表该项通过。
  [Rust OnceLock 文档](https://doc.rust-lang.org/std/sync/struct.OnceLock.html)
- 生产暂定只新增实测所用 `sha2 0.10.9` 系列用于完整性检查；flate2、serde 和
  serde_json 只属于独立探针，不成为当前公共 crate 的依赖。后续 Unicode 依赖或
  派生表在对应实现阶段确认 MSRV 与许可；不得降低 Python 行为精度来满足预算。

## 可复核边界

准备脚本拒绝覆盖不同的已有原型产物，输入前后指纹一致；重复准备应完全一致。
独立 Python 解码与四个 Rust 候选的全量逻辑 FNV 均为 `b43994db8bc9403a`，
逻辑 SHA-256 为 `30c5cd54d9fcf6cc7bdf0d8d99dd7d87f9763e3f65189596aae3c972702d2bd3`。
FNV 仅用于跨解析器的一致性检查，完整性以资源 SHA-256 为准。
154 条 P0 snapshot 查询、标签和完整有序分类列表向量通过；这不包含错误、
隔离夹具、标注或全部 50,335 词逐公共 API 差分。

P2.1 已提供生产导出、来源清单、全记录字段验证、篡改检测及可重复性检查，
见[导出说明](data-export.md)及[全量对照证据](data-verification.json)；
P2.2 已验证资源错误、并发及只读索引；P2.3–P4 仍须实现并验证全部公共查询、
Unicode/标注语义和实际性能预算。

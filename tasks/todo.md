# Lingose Rust 0.1.0 执行计划

需求依据：[TASK.md](../TASK.md)。开发约束：[AGENTS.md](../AGENTS.md)。当前恢复点：[handoff.md](handoff.md)。

目标：发布名为 `lingose` 的 Rust 库 `0.1.0`，实现 Python README 公共函数（排除 `lookup`），随包提供完整必要数据，安装后离线查询和标注，并满足经实测固定的性能预算。

按编号顺序执行；每次完成一个小任务，记录验证并聚焦提交。仅实际完成并验证后勾选，未开始的工程和发布工作不得标为完成。

## P1：Rust 接口、工程与数据方案

- [ ] P1.1 建立 crate 骨架并固定 Rust 接口。
  - 依赖：P0.2。设置名称 lingose、版本 0.1.0、edition、最低 Rust 版本与依赖策略；确定同步调用、类型、默认参数表达、返回值所有权、错误类型及大小写别名。
  - 产物：最小可检查工程、接口说明和基础示例；标明最低版本验证状态。
  - 验收：接口覆盖行为矩阵，参数错误与未知词分离，编译和最小相关检查通过；不以未实现的占位结果冒充 API 完成。
- [ ] P1.2 比较数据布局并固定加载、索引和性能预算。
  - 依赖：P1.1。用完整必要数据比较紧凑静态索引、压缩加载等可行方案，测量体积、冷初始化、热查询、词表和内存；确定只读数据复用与并发策略。
  - 产物：Rust 数据格式、加载/索引约定及性能预算，含可重复命令、机器、工具链和语料身份。
  - 验收：选择有实测依据，覆盖完整离线数据；有真实压缩归档的体积估算，不能直接携带约 89 MB 的完整 Python 压缩库。

## P2：可重复数据导出与单词查询

- [ ] P2.1 实现受基线保护的数据导出和校验。
  - 依赖：P1.2。投影有效采用值、标注资格、分类排序和原始频率阈值；生成版本、计数、SHA-256 及来源/许可证清单。
  - 验收：完整记录覆盖、字段值和空值状态对照通过；输入未修改，重复导出一致，篡改输入或输出能被检测。
- [ ] P2.2 实现数据加载与查询索引。
  - 依赖：P2.1。按固定方案复用只读数据，验证格式/版本并支持并发调用；错误不得转为未知词。
  - 验收：冷/热调用、并发访问、格式不兼容和损坏资源路径通过相关检查；不依赖源码目录或额外数据下载。
- [ ] P2.3 实现发音、构词、词族和释义查询。
  - 依赖：P2.2。完成 ipa/IPA、ips/IPS、ism/ISM、ipsm/IPSM、root_lemma、meaning。
  - 验收：样例、精确/小写回退、缺失及无效数据、en/zh、别名行为均与固定基线一致；不补用未采用候选。
- [ ] P2.4 实现分类及完整有序词表。
  - 依赖：P2.3。完成 kind、kind_list、labels，保留默认 CET4、标签大小写、成员和词族/rank/原词业务排序。
  - 验收：每个注册分类的成员与完整顺序均与 Python 一致，非法标签错误与未知词 false 结果分离。
